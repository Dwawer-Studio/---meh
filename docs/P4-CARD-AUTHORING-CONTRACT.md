# عقد تأليف وإصدار بطاقة P4

## ما لا يجوز البدء بدونه

قبل الرسم أو الإعلان، يكتب صاحب البطاقة:

1. القرار الذي تضيفه البطاقة ولا توفره بطاقة حالية.
2. أثرها بالعربية والإنجليزية بصياغة قابلة للتنفيذ.
3. الرد المضاد الذي يستطيع الخصوم اتخاذه.
4. حالات الحافة مع السحب المعلّق، الدرع، تعطيل القوى، تبديل الاتجاه والمرمي.
5. خطرها على طول المباراة: `low|medium|high`.
6. `replacementClass` و`powerBudget` و`replacementAnchorDefinitionId` لبطاقة
   أساس موجودة في classic من الفئة والميزانية نفسيهما.
7. تسمية وصولية عربية/إنجليزية لا تعتمد على اللون أو الرسم وحده.
8. `gameplayTargetMatches` وسعر تاماشي داخل band النموذج المعتمد.
9. content flag خاص وحالة `candidate`.

يرفض `validateCatalogManifest` تعريف التوسعة إن غاب أي بند، أو كان مدفوعًا
حصريًا، أو بلا تجربة/مسار لعب، أو استخدم opcode غير موجود في Core Manifest.
إضافة opcode جديد ليست محتوى P4؛ هي تغيير rulesVersion ومراجعة Core مستقلة.
الـschema مغلق بلا حقول خفية، والحد 256 تعريفًا و128 وصفة و16 حالة حافة، وملف
الإصدار الموقّع لا يتجاوز 2 MiB.

## خط الإصدار

```text
فرضية القرار
→ state table وحالات الحافة
→ تعريف schema + نص AR/EN + وصولية
→ invariant/loop tests
→ 100,000 مباراة لكل تعريف وكل وصفة متأثرة
→ اختبار بشري أعمى
→ تحديث التطبيق وفيه التعريف والآرت
→ catalog موقّع وحالة friendly-5
→ 5% من الغرف الودية
→ تحليل guardrails
→ live/standardized recipe أو إيقاف
```

لا تصدر بطاقة لأن موعد التقويم وصل. ولا تدخل public/ranked لمجرد أن 100 ألف
محاكاة نجحت؛ المحاكاة تثبت السلامة لا المتعة.

## التوقيع وقفل الأساس

ينشأ المفتاح الخاص Ed25519 ويحفظ في KMS/HSM خارج المستودع وخارج متغيرات تشغيل
اللعبة. ملف التعريف يوقع في بيئة إصدار منفصلة:

```text
node tools/sign-catalog.js --manifest catalog.json --private-key catalog-private.pem --out catalog-envelope.json
```

الأداة ترفض schema غير صالحًا، مفتاحًا غير Ed25519، أو الكتابة فوق ملف الإدخال.
بعد التوقيع يتحقق الخادم مرة ثانية قبل التفعيل. لا يجوز للكتالوج اللاحق تعديل أو
حذف أي تعريف أو وصفة مسجلة، ولا إضافة تعريف جديد كـ`availableByDefault`، ولا
إعادة استخدام إصدار `1.0.0` أو إصدار أقدم. تعريف التوسعة immutable باستثناء
انتقال حالة أحادي الاتجاه: `candidate → friendly-5 → live/disabled`؛ الرجوع
التشغيلي يتم بالـcontent flag ولا بتغيير هوية البطاقة.
الوصفة العامة الجديدة لا تقبل تعريفًا غير `live`.

## معنى الملكية

- فتح البطاقة يمنح حق اقتراحها في غرفة ودية، لا حق وضعها في يد اللاعب.
- كل مقعد يساهم بصفر أو بطاقة واحدة.
- الخادم يستبدل بطاقة واحدة من الفئة والميزانية نفسيهما.
- الوصفة النهائية ظاهرة للجميع، وعند بدء المباراة تصبح الرزمة مشتركة بالكامل.
- quick/public تستعمل وصفة معيارية واحدة لا تعتمد على ملكيات الجالسين.
- المجلس القديم يبقى على `classic-60-v1` ما لم يعتمد الجالسون وصفة ودية صراحة.

## أوامر البوابة

- `npm run test:p4`
- `npm run test:p4:simulation`
- `npm run test:p4:economy`
- `npm run check`
- `npm run check:clean`
- `npm audit --audit-level=high`

لكل تعريف إنتاج جديد يجب أن يثبت التقرير: صفر loop، صفر card loss، صفر replay
mismatch، صفر unknown definition، مع قياس مدة المباراة وتغطية التفاعلات.
