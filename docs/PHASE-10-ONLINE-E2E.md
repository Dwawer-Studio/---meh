# المرحلة 10 — اختبار اللعب الجماعي بعميلين حقيقيين

## النطاق

تغلق هذه المرحلة فجوة الاختبار الواقعي لمسار اللعب عبر الشبكة. يعمل عميلان
مستقلان داخل متصفحي Chromium، ولكل عميل سياق وتخزين محلي وهوية PeerJS خاصة.
لا تُستبدل قناة البيانات بكائن وهمي ولا تُستدعى رسائل اللعبة مباشرة.

تشمل بوابة القبول:

- إنشاء المضيف غرفة فعلية وقراءة كودها من الواجهة.
- دخول العميل بالكود ووصول قائمة اللاعبين إلى الطرفين.
- قطع قناة بيانات العميل عمدًا وإنشاء قناة جديدة بمعرّف مختلف.
- استعادة عضوية العميل في صالة الانتظار بعد الانقطاع.
- بدء المضيف المباراة عبر القناة المستعادة ووصول الحالة إلى العميل.
- توزيع سبع بطاقات لكل لاعب في الطرفين.
- سحب المضيف بطاقة ووصول الدور إلى العميل.
- سحب العميل بطاقة ووصول العدد الجديد إلى واجهة المضيف.
- الفشل عند ظهور خطأ JavaScript أو Console أو استجابة محلية بحالة `4xx/5xx`.

## التنفيذ

- أضيف خادم PeerJS الرسمي `peer@1.0.2` كاعتماد تطوير مقفول. يبدأ الخادم محليًا
  على `127.0.0.1:9001` أثناء ملف الاختبار ويُغلق خادم HTTP صراحة بعده.
- أضيفت إعدادات PeerJS اختيارية عبر `window.MEH_PEER_OPTIONS`. عند غيابها تبقى
  استدعاءات الإنتاج كما كانت تمامًا: معرّف فقط للمضيف، ومنشئ بلا معاملات
  للعميل. أثبت اختباران وحديان هذا العقد وإمرار الإعداد الصريح للطرفين.
- يستخدم الاختبار نسخة عميل PeerJS الرسمية المقفلة `1.5.4` نفسها التي تعتمدها
  الصفحة، مع الحفاظ على فحص SRI.
- تُعطّل ميزة إخفاء عناوين WebRTC المحلية خلف mDNS في Chromium الخاص
  بالاختبارات فقط. سياقا Chromium المعزولان لا يستطيعان حل أسماء mDNS المتبادلة
  بصورة موثوقة، بينما يحتاج الاختبار إلى مرشحات ICE محلية قابلة للتكرار.
- تُضبط `iceServers` على قائمة فارغة في الاختبار كي لا يعتمد نجاح البوابة على
  STUN خارجي أو اتصال إنترنت.

## العيب الذي كشفته المرحلة

أثبت التشغيل الأول أن خادم الإشارة تبادل `offer` و`answer` ومرشحات ICE بنجاح،
لكن قناة البيانات بقيت مغلقة لأن Chromium أخفى عناوين الشبكة المحلية بأسماء
mDNS مختلفة بين السياقين المعزولين. عولجت بيئة الاختبار بخيار تشغيل Chromium
المخصص للاختبار؛ لم يتغير سلوك متصفح المستخدم أو إعداد الاتصال الافتراضي.

  ظهر المضيف والضيف في الطرفين، وبدأ كل طرف بسبع بطاقات، ووصل سحب كل طرف
  وعدده الجديد إلى الطرف الآخر. لم تظهر حالة خطأ أو رسالة خطأ مرئية.

## حدود المرحلة

- خادم PeerJS المحلي ينسّق إنشاء الاتصال فقط؛ لا يعمل كمرحّل لحركة اللعبة.
- لا تختبر هذه المرحلة جهازين على شبكتين عامتين مختلفتين أو المرور عبر NAT
  مقيد. ما زال قرار TURN واختبار النشر العام ضمن مرحلة النشر المؤجلة.
- إعداد `MEH_PEER_OPTIONS` مسار تشغيل اختياري للاستضافة الذاتية والاختبارات؛
  لا تضع الصفحة الحالية إعدادًا له، لذلك يبقى اتصال الإنتاج الافتراضي كما كان.

## بوابة الإغلاق

- لا يستطيع تعطل إنشاء الغرفة أو الانضمام أو الاستعادة أو بدء اللعبة أو مزامنة
  السحب المرور عبر `npm run test:e2e` أو CI.
- لا تعتمد البوابة على خادم إشارة عام أو CDN أو STUN خارجي أثناء السيناريو.
- يجب أن تبقى اختبارات المراحل 0–9 ناجحة مع فحص لقطة عمل نظيفة.
