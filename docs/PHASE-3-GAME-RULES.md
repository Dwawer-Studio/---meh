# المرحلة 3 — سلامة قواعد البطاقات وتكافؤ التأثيرات

## النطاق

تغلق هذه المرحلة البندين `RULE-01` و`RULE-02` المسجلين في خط الأساس:

- بقاء البطاقات الستين في الرزمة أو الأيدي أو المرمي بعد كل تأثير.
- تنفيذ انتقال الحالة نفسه عندما يكون صاحب البطاقة لاعباً محلياً أو بوتاً أو
  لاعباً بعيداً، مع اختلاف وسيلة الحصول على القرار فقط.

لا تشمل المرحلة إكمال دور كامل بلوحة المفاتيح؛ يظل `A11Y-01` ظاهراً كاختبار
`TODO` للمرحلة المخصصة لإمكانية الوصول.

## الإصلاحات المنفذة

### حفظ الرزمة

- نُقلت كل بطاقة يجري التخلص منها إلى المرمي بدل حذفها من اليد وضياعها.
- توضع البطاقات المتخلص منها تحت بطاقة التأثير الحالية؛ لذلك لا تصبح أعلى
  المرمي، ولا تغير اللون النشط، ولا ينفذ تأثيرها كأنها لُعبت.
- أصبحت البطاقة الافتتاحية من نوع `normal` حصراً، فلا يبدأ تأثير خاص من دون
  تنفيذه.
- يغطي اختبار الحفظ كل نوع تأثير في الرزمة، ولكل من مسارات المضيف والبوت
  واللاعب البعيد، مع فحص العدد 60 وتفرّد المعرّفات.

### تكافؤ التأثيرات

- فُصل اتخاذ القرار عن تطبيق التأثير. اللون والهدف والخيار والبطاقة تمر الآن
  عبر بوابة قرار واحدة، ثم يطبق الجميع دالة التأثير نفسها.
- يستطيع اللاعب البعيد اختيار البطاقة الدقيقة في تأثيري `الحرباية` و`بوشلاخ`
  بدلاً من الاختيار العشوائي نيابة عنه.
- ترتبط إجابة اختيار البطاقة بمعرّف الطلب واللاعب المقصود وقائمة معرّفات
  مسموحة؛ تُرفض القيم غير المعروضة أو المكررة أو المشوهة.
- أصبحت ردود عقوبة السحب قائمة واحدة مشتركة بين الواجهة والبوت والمضيف
  والتحقق الشبكي: `draw2` و`draw4Wild` و`meh` و`counterAttack` و`phantom`.
- مدة `شوقر` دورة طاولة كاملة تنتهي عند عودة الدور إلى صاحبها، بدلاً من 15
  ثانية تتأثر بسرعة الجهاز والحركات.

القرارات المعتمدة كاملة موثقة في `docs/RULES-DECISIONS.md`.

## التحقق الآلي

```bash
npm run test:rules
npm run check
npm run check:clean
npm audit --audit-level=high
```

تتحقق اختبارات القواعد من جميع أنواع التأثيرات الموجودة فعلياً في `Deck`، ولا
تعتمد على قائمة يدوية قد تنسى بطاقة جديدة. لكل نوع يُفحص حفظ 60 معرفاً فريداً،
ثم تقارن لقطة انتقال الحالة بين المضيف والبوت واللاعب البعيد عند القرارات نفسها.

نتيجة البوابة النهائية في 2026-08-27:

- `npm run test:rules`: 55 اختباراً ناجحاً، 0 فشل، 0 مؤجل.
- `npm run check`: 91 اختباراً إجمالاً؛ 90 ناجحاً، 0 فشل، وحالة `TODO` واحدة
  هي `A11Y-01` خارج نطاق المرحلة.
- `npm run check:clean`: ناجح بعد تثبيت 125 حزمة في لقطة Git مؤقتة ونظيفة،
  مع نجاح البوابة وبقاء الشجرة المعزولة نظيفة بعدها.
- `npm audit --audit-level=high`: لم يعثر على أي ثغرة.
- لا يبقى أي `TODO` تابع لـ`RULE-01` أو `RULE-02`.

## تحقق المتصفح الحقيقي

شُغّل الفرع محلياً واختُبر من الواجهة المرئية:

1. بدأت مباراة محلية بسبع بطاقات وبطاقة افتتاحية من نوع `normal`، ثم رُميت
   بطاقة صالحة فانخفضت اليد إلى ست بطاقات.
2. أُنشئت غرفة أونلاين وانضم عميل؛ ظهر لاعبان في الردهة عند الطرفين.
3. بدأت المباراة بسبع بطاقات لدى المضيف والعميل، وتطابقت بطاقة المرمي العليا
   في الشاشتين.
4. كانت سجلات المباراة المحلية والمضيف والعميل خالية من الأخطاء والتحذيرات.

## حدود المرحلة

- اختلاف اختيار البوت التلقائي عن اختيار الإنسان ليس اختلافاً في قاعدة التأثير؛
  جميع الاختيارات الصالحة تمر إلى التطبيق المشترك نفسه.
- يبقى المضيف هو صاحب حالة المباراة في نموذج اللعب الودي الحالي.
- دعم TURN مخصص قرار نشر لاحق، وإمكانية الوصول بلوحة المفاتيح ضمن المرحلة
  التالية المخصصة لها.
