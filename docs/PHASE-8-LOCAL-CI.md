# المرحلة 8 — التشغيل المحلي وفصل الاختبارات عن النشر

## النطاق

تعتمد هذه المرحلة التشغيل المحلي حتى انتهاء العمل، وتفصل بوابة الجودة عن
خدمة النشر الخارجية. لا تغيّر اللعبة أو قواعدها أو بروتوكولها.

## سبب المرحلة

كان Workflow واحد يجمع فتح Pull Request مع نشر Azure مباشرة. أثبت سجل
GitHub Actions أن البناء وصل إلى Azure، ثم رُفض لأن المفتاح لا يطابق Static
Web App صالحًا. كما أثبت فحص اشتراك Azure الحالي عدم وجود أي Static Web App.

إنشاء مورد مدفوع أو تعطيل الفحص لتجاوز الخطأ ليس جزءًا من القرار. المطلوب هو
الاستمرار محليًا مع بوابة جودة مستقلة، وتأجيل النشر حتى اختيار الاستضافة.

## التنفيذ

### بوابة CI مستقلة

أضيف `.github/workflows/ci.yml` ليعمل على:

- كل Pull Request.
- `main` وفروع `hardening/**` عند الدفع.

تنفذ البوابة تثبيت الاعتماديات المقفلة، ثم `npm run check`، ثم تدقيق الثغرات
عالية الخطورة. صلاحيتها الوحيدة هي قراءة محتوى المستودع، وتلغي التشغيل السابق
عند وصول تحديث أحدث إلى المرجع نفسه.

ثُبتت Actions الخارجية على بصمات كوميت كاملة موثقة بدل وسوم قابلة للتغيير،
ويحمي الاختبار هذه البصمات من الرجوع غير المقصود.

### Azure يدوي فقط

احتُفظ بـWorkflow Azure بدل حذفه، لكن أصبح يقبل `workflow_dispatch` فقط ويتطلب
تأكيدًا منطقيًا صريحًا. أزيلت محفزات `push` و`pull_request` ومهمة إغلاق بيئة
المعاينة؛ لذلك لا يستطيع مفتاح Azure القديم تعطيل فروع التطوير أو طلبات الدمج.

عندما تصبح الاستضافة جاهزة، يلزم إنشاء التطبيق وتحديث السر قبل تشغيل هذا
Workflow يدويًا.

## حماية القرار

يمنع `tests/workflows.test.js` التراجع عبر التحقق من:

- وجود CI مستقل وتشغيله للأوامر المطلوبة.
- عدم احتواء CI على خطوة نشر Azure.
- اقتصار Azure على التشغيل اليدوي.
- بقاء إعداد النشر محفوظًا للمستقبل من دون محفزات تلقائية أو مهمة إغلاق PR.

## بوابات الاختبار

```bash
npm run test:workflows
npm run check
npm run check:clean
npm audit --audit-level=high
```

نتيجة البوابة المحلية في 2026-08-28:

- اختبارا Workflows ناجحان بعد إثبات فشلهما على الإعداد القديم.
- `npm run check`: 110 اختبارات ناجحة، 0 فشل، 0 مؤجل.
- ملفا Workflow يمران بتحليل YAML فعلي.
- لا توجد تغييرات في ملفات تشغيل اللعبة أو واجهتها.

## بوابة الإغلاق

- التشغيل المحلي لا يعتمد على Azure.
- PR والفروع يشغّلان الاختبارات من دون نشر خارجي.
- النشر لا يحدث إلا بطلب يدوي مؤكد بعد تجهيز الاستضافة.
- بوابات المراحل 0–7 ما زالت ناجحة.
