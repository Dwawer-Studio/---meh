# المرحلة 9 — اختبارات المتصفح الفعلية

## النطاق

تضيف هذه المرحلة بوابة متصفح حقيقية لمسارات الاستخدام المحلية التي كانت
مغطاة سابقًا باختبارات منطقية وتحقق يدوي فقط. لا تغيّر قواعد البطاقات أو
بروتوكول اللعب الشبكي أو قرار النشر المؤجل.

تشمل بوابة القبول:

- إنشاء عضو جديد من الواجهة وحفظه.
- بدء مباراة محلية وانتظار توزيع سبع بطاقات لكل لاعب.
- معاينة بطاقة متاحة وإلغاء المعاينة، ثم إكمال الدور بالسحب.
- إتمام المسار الأساسي بلوحة المفاتيح.
- الوصول إلى شاشة النهاية والعودة إلى القائمة.
- قياس عناصر الطاولة الأساسية عند `1280 × 720` و`390 × 844` و`844 × 390`.
- الفشل عند خطأ JavaScript أو خطأ Console أو استجابة محلية بحالة `4xx/5xx`.

## التنفيذ

- أضيف Playwright بإصدار مقفول وإعداد Chromium واحد وعامل واحد لمنع تداخل
  بيانات الجلسات ومنافذ الخادم.
- يشغّل الاختبار خادم المشروع داخل عملية الاختبار نفسها ويغلقه صراحة بعد
  السيناريوهات؛ بذلك تنتهي البوابة طبيعيًا على Windows وLinux ولا تعيد استخدام
  خادم قديم من نسخة عمل أخرى.
- تعزل كل رحلة بيانات `localStorage` وتستخدم مولدًا عشوائيًا ثابت البذرة، لذلك
  تبقى الرزمة والنتائج قابلة للتكرار.
- تُخدّم نسخة PeerJS الرسمية `1.5.4` من الاعتماد المقفول أثناء الاختبار. الملف
  هو نفسه الذي تشير إليه صفحة التشغيل وتطابق بصمته `sha384`؛ لا يجري تعطيل SRI
  أو استبدال المكتبة بكود وهمي.
- أصبحت `npm run check` تشغّل اختبارات المتصفح بعد بوابات الصياغة والجودة
  والاختبارات المنطقية، ويثبت CI متصفح Chromium قبل تشغيلها.

## العيب الذي كشفته المرحلة

أثبت التشغيل الأول عند `844 × 390` أن نموذج إنشاء العضو أطول من لوحة الهاتف
الأفقية، وأن زر الحفظ يقع خارج نافذة العرض ولا يستطيع المستخدم الوصول إليه.
أضيف تمرير رأسي داخلي إلى لوحة العضو في التخطيط الأفقي القصير. يحمي اختبار
الهاتف الأفقي رحلة الإنشاء والحفظ قبل الانتقال إلى اللعبة، فلا يمكن أن يعود
القص بصمت.

```bash
npm run check
npm run check:clean

```

## حدود المرحلة

- تختبر المرحلة اللعب المحلي في متصفح حقيقي، ولا تدّعي اختبار اتصال جهازين
  فعليين عبر PeerJS أو شبكات تحتاج TURN.
- يبقى تجهيز الاستضافة وتشغيل نشر Azure وقرار TURN ضمن مرحلة النشر العامة.

## بوابة الإغلاق

- لا يستطيع عطل في رحلة سطح المكتب أو لوحة المفاتيح أو تخطيط الهاتف المرور
  عبر `npm run check` أو CI.
- خادم الاختبار يبدأ من ملفات اللقطة الحالية ويغلق من دون عملية معلقة.
- اختبارات المراحل 0–8 ما زالت ناجحة.
