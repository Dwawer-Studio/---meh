# تقرير المرحلة P3 — المجلس العائد

التاريخ: 2026-08-28

الحالة: `Engineering Complete / Validation Deferred`

لا تصبح الحالة `Engineering Complete` إلا بعد نجاح كل البوابات المدرجة في
هذا التقرير وتطابق رأس الفرع المحلي والبعيد. ولا تعني الحالة الهندسية أن فرضية
عودة المجموعة ثبتت؛ الاختبارات البشرية والأفواج وSLA التشغيلية محفوظة في
`docs/DEFERRED-VALIDATION-REGISTER.md`.

## حدود المرحلة

P3 تبني ذاكرة اجتماعية اختيارية حول المباراة الثابتة:

- لا تغيير لتعريف بطاقة أو آرت أو وصفة الرزمة أو المطابقة أو السحب أو الدور أو
  الفوز.
- لا تاماشي، متجر، شراء بطاقة، Deck شخصي، streak، daily reward، contacts،
  رسالة حرة، أو matchmaking عام جديد.
- كل شريحة واجهة خلف علم مستقل، وأعلام P3 الإنتاجية مطفأة افتراضيًا. التشغيل
  المحلي `?service=local` يفتحها للاختبار فقط.

## قائمة الإغلاق الهندسي

- [x] تأسيس مجلس من شاشة نتيجة موثوقة فيها بشران على الأقل.
- [x] المالك وحده يدخل تلقائيًا؛ كل لاعب آخر يقبل صراحة من source room نفسه.
- [x] اسم NFKC بحد 32 ومنع control/bidi overrides، وcosmetics من allowlist.
- [x] عضوية خادمية تمنع IDOR والدخول عبر room code لغير العضو.
- [x] «اجمع المجلس» يعيد استخدام غرفة FORMING واحدة ذريًا؛ لا تتفرع الغرف عند
  ضغط عضوين معًا، ولا يبدأ مجلس غرفة ثانية أثناء مباراة نشطة.
- [x] سجل جلسات وحصيلة مجلس idempotent، مع دعم أسماء عرض مكررة دون دمج حسابين.
- [x] موعد 15 دقيقة–30 يومًا وتذكير اختياري claim ذري بلا إشعار مكرر.
- [x] ست عبارات دردشة ثابتة، cooldown، كتم محلي فوري، وبلاغ بشري ضد بشري في
  طاولة عامة موثوقة فقط.
- [x] طابور بلاغات يحتفظ بالمفتوح، audit لكل تغيير، ومسارات loopback محمية بسر
  مشغّل مستقل إلزامي في الإنتاج.
- [x] حذف الغرفة بعد 30 يومًا لا يمحو جلسة المجلس أو البلاغ المفتوح؛ البلاغ
  المغلق/المرفوض يحذف بعد 180 يومًا.
- [x] PostgreSQL migration وMemoryStore ونسخة منطقية/استعادة يحفظان الروابط
  الدائرية والموافقات والجلسات والبلاغات.
- [x] HMAC منفصل النطاق للمجلس والمباراة، ولا اسم/room code/account id في
  telemetry المنتج.
- [x] تعيين تجريبي ثابت 50/50 لكل تثبيت، تجربة P3 واحدة فقط، فشل آمن، وكشف
  crossover وإزالة التكرار وتحليل Wilson/Newcombe.
- [x] سجل الاختبارات البشرية/الميدانية المؤجلة مكتمل بشروط نجاح مقفلة.
- [x] البوابة النهائية الكاملة نجحت؛ clean snapshot موثق أدناه، ويثبت تطابق
  push بعد إنشاء commit النهائي.

## عقد الخدمة المختصر

WebSocket المضاف: `majlis.create`، `majlis.accept`، `chat.send`،
`report.submit`. أخطاء المجال تعود `social.rejected` ولا تتحول إلى نجاح صامت.

HTTP المصادق عليه: `GET /v1/majalis`، `GET /v1/majalis/<id>`، إنشاء دعوة
مجلس، ضبط تذكير، وclaim للتذكيرات المستحقة. مسارات
`/internal/moderation/reports` ليست API عامًا؛ loopback + رمز المشغّل في
الإنتاج، ويجب حجبها كذلك في طبقة الشبكة.

## التجارب وعدم ادعاء النتيجة

الأعلام الأربعة التجريبية مرتبة ولا تعمل متوازية:

1. `recent_majalis` — E01.
2. `one_tap_reinvite` — E02 بعد نجاح E01.
3. `majlis_session_score` — E03 بعد نجاح E02.
4. `majlis_schedule` — E04 بعد نجاح E03.

`safe_quick_chat` سطح سلامة مستقل وليس ذراع احتفاظ. تقرير schema v4 يحسب
W1-GR بأيام الرياض، أفواج الاثنين، الوحدات الناضجة، النتائج بحسب الذراع، فاصل
Wilson لكل نسبة وفاصل Newcombe للفرق. لا يعطي `positive` إذا كان الحد الأدنى
غير موجب، ولا يخفي التثبيت الذي ظهر في ذراعين.

PostgreSQL مُدار أو p95 إقليمي. قياسات البشر والشبكة والتشغيل تبقى مؤجلة كما
هي، ولا تستبدلها هذه الأرقام.
