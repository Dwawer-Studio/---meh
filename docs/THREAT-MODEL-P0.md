# نموذج التهديد — P0

التاريخ: 2026-08-28

## الأصول وحدود الثقة

الأصول المستقبلية هي رصيد تاماشي، ملكية البطاقات، نتيجة المباراة، وصفة الرزمة،
وحساب اللاعب. المتصفح و`localStorage` والمضيف الحالي وPeerJS كلها خارج حد الثقة
لأي قيمة اقتصادية. ملفات manifest المضمنة مرجع عميل واختبار، وليست تفويضًا لمنح
رصيد. الخدمة الخادمية المستقبلية وحدها تملك دفتر الاقتصاد وقرار النتيجة الموثقة.

## التهديدات والضوابط

| التهديد | الأثر | الضابط الحالي | المطلوب قبل P4 |
|---|---|---|---|
| تعديل العميل أو المضيف للنتيجة | سك عملة أو فوز مزيف | لا اقتصاد مفعل؛ replay وبصمات | محرك خادمي صاحب سلطة |
| إعادة طلب مكافأة أو شراء | مضاعفة الرصيد | العقد يمنع منح العميل | idempotency ومفتاح عملية فريد |
| تلاعب بسعر/تعريف بطاقة | شراء خاطئ أو تنفيذ ضار | manifest مجمد وopcode مقيد | كتالوج موقع وخادمي |
| AFK أو تواطؤ ومباريات مصطنعة | تضخم العملة | لا مكافآت في P0 | أهلية، حدود سرعة، كشف عناقيد |
| خصم/إضافة غير ذريين | رصيد سالب أو ملكية بلا دفع | غير منفذ | معاملة دفتر واحدة وسجل تدقيق |
| replay قديمة مع محتوى جديد | نتيجة غير قابلة للتفسير | ثلاثة إصدارات مسجلة | احتفاظ بالعقود وترحيل صريح |
| تسريب اليد أو الاسم في القياس | انتهاك خصوصية/غش | مخطط قائمة سماح وحظر حقول | تنقيح خادمي وسياسة حفظ |
| تكرار إرسال الحدث | تضخيم المقاييس | `eventId` وطابور بإقرار | إزالة تكرار عند الاستقبال |
| شراء مُلغى أو مسترد | رصيد غير مغطى | مصدر شراء موثق فقط في العقد | تحقق متجر وتسوية واسترداد |
| شراء بطاقة أقوى | Pay-to-win | مسار لعب لكل بطاقة ووصفة مصنف موحدة | بوابة توازن وطرح محدود |

## إساءة اقتصادية يجب اختبارها

- فتح حسابات متعددة وتبادل الانتصارات.
- إنهاء المباراة بأقصر مسار أو قطع الاتصال لحصد الإكمال.
- تكرار receipt أو webhook وسباق عمليتي صرف للرصيد نفسه.
- الرجوع بإصدار عميل قديم لشراء سعر قديم أو استخدام بطاقة موقوفة.
- تجاوز حد الرزمة الودية أو استبدال بطاقة من فئة قوة مختلفة.

## بوابة عدم التجاوز

لا نفعّل شراء تاماشي أو منحها أو ملكية بطاقات حقيقية حتى توجد خدمة خادمية،
تحقق إيصال، دفتر معاملات ذري، idempotency، سجل تدقيق، وسياسة استرداد. P0 يؤسس
العقود والأدلة فقط ولا يدعي أن الاقتصاد أصبح جاهزًا للإنتاج.
