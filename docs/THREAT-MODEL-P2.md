# نموذج تهديد P2 — الخدمة الاجتماعية

التاريخ: 2026-08-28

## الأصول وحدود الثقة

الأصول الحساسة هي أوراق كل مقعد، ترتيب الرزمة، رموز الجلسة والاستعادة، نتيجة
المباراة الموثوقة، وربط الحساب بالمجلس. كود الغرفة عنوان قابل للمشاركة وليس
سرًا. تنتهي ثقة العميل عند WebSocket؛ لا يملك اسم المقعد أو الوقت أو صلاحية
تطبيق حركة.

```text
متصفح غير موثوق
  → TLS / origin / schema / rate limit
خدمة WebSocket صاحبة السلطة
  → معاملة + parameterized SQL
PostgreSQL
```

## التهديدات والضوابط

| التهديد | الأثر | الضابط المنفذ | الدليل المطلوب |
|---|---|---|---|
| تزوير حركة أو مقعد | لعب ورقة ليست للفاعل | ربط الاتصال بمقعد؛ actor يستخرج خادميًا؛ reducer يتحقق من الدور والملكية | اختبار `CARD_NOT_OWNED` و`OUT_OF_TURN` |
| إعادة رسالة ناجحة | سحب/لعب مزدوج | `(roomId, requestId)` مربوط بالمقعد والحساب؛ فحص الإقرار المخزن داخل قفل الغرفة وقبل تعارض الحالة | اختبار stale-state duplicate وإعادة الطلب بعد استرجاع المقعد |
| إعادة ترتيب/قفز | تجاوز حالة | `clientSeq` متصل و`serverSeq`/snapshot وبصمة | اختبارات stale/gap/resync |
| تخمين كود غرفة | دخول غير مأذون واسع | rate limit بحسب IP hash؛ الكود لا يمنح مقعدًا بلا جلسة؛ الغرفة لها سعة وحالة | اختبار rate limit وroom full |
| إغراق إنشاء/ترقية/دخول الحساب | استنزاف DB/CPU عبر `scrypt` | bucket مستقل بحسب IP ونطاق العملية قبل قراءة الجسم أو التشفير؛ `429` و`Retry-After`؛ فشل دخول موحد | اختبار HTTP وتحقق اعتماد صحيح/خاطئ |
| سرقة رمز استعادة | خطف مقعد | 256-bit، بصمة فقط في DB، 30 ثانية، تدوير بعد النجاح وإلغاء بالمغادرة | اختبار once-only/expiry |
| كشف أوراق الخصوم | كسر النزاهة | `publicView` خاص بكل مقعد؛ لا deck order ولا hands أخرى | اختبار redaction |
| عميل يفرض timeout/بوت | تغيير نتيجة | البروتوكول العام يقبل `play` و`draw` فقط؛ scheduler الداخلي يكتب system action | اختبار رفض `timeout` |
| JSON/ضغط ضخم | استنزاف ذاكرة | `maxPayload=16KiB`، ضغط WebSocket معطل، hello خلال 5s | اختبار الحجم والمهلة |
| اتصالات ميتة | تسرب غرف/ذاكرة | ping/pong كل 10s وإنهاء بعد دورتين، lease ثم bot takeover | اختبار heartbeat/lease |
| حقن SQL أو stack | وصول قاعدة/أسرار | معاملات parameterized، أنواع رسائل ثابتة، `server.error` يعرض incident code فقط | فحص الكود واختبار payload |
| سرقة DB/نسخة | كشف الهوية | access/recovery hashes، نسخة منطقية AES-256-GCM، TLS لقاعدة الإنتاج | اختبار عدم وجود raw token وtamper |
| حذف شكلي | خرق خصوصية | حذف الحساب والجلسات، فصل FK من actions/audit، tombstone للاستعادة | اختبار حذف فعلي |
| اعتماد ضعيف | RCE/DoS سلسلة توريد | نسخ exact وlockfile و`npm audit --audit-level=high` | بوابة P2 |

## إساءة منطق اللعبة

- معدل فعل الاتصال burst 8 ثم 4/ثانية؛ الرفض لا يغير حالة المباراة.
- الخادم يسجل الفعل الملتزم وبصمة الناتج، ويسجل رفض البروتوكول مع IP مموه.
- لا تمنح P2 تاماشي بعد؛ P4 لا يقبل نتيجة إلا من هذا المسار وبسياسة مكافحة
  التواطؤ المستقلة.
- لا دردشة نصية حرة في هذه المرحلة، لذلك لا تخزن الخدمة محتوى مستخدم غير اسم
  العرض المقيد والإيموجي المحدود في العميل الحالي.

## المتبقي التشغيلي

- حماية DDoS/WAF وتدوير أسرار الخدمة مسؤولية منصة النشر ولا تثبت محليًا.
- TLS ينتهي عند proxy موثوق معزول يرسل `x-forwarded-proto=https`; وضع production
  يرفض كل `/v1/*` وغير WSS دون ذلك. لا يثق بـ`X-Forwarded-For` إلا عند تفعيل
  `MEH_TRUST_PROXY` الصريح.
- اختبار PITR وRPO/RTO الحقيقي مسجل `P2-O01`، والطرح الإقليمي `P2-O02`.
