# نموذج تهديد P4 — كتالوج البطاقات وتاماشي

التاريخ: 2026-08-28

## الأصول وحدود الثقة

الأصول هي رصيد تاماشي، دفتر القيود، إيصال المتجر المتحقق، فتح البطاقة، تعريف
الكتالوج الموقّع، وصفة الرزمة المقفلة، مساهمة كل مقعد، وإمكانية إعادة المباراة.
العميل وPeerJS وحقول HTTP غير موثوقة. PostgreSQL وخدمة المباراة ومحوّل إيصال
المتجر الحقيقي وحدها مصادر السلطة.

P4 الحالية لا تشحن تعريف بطاقة إنتاج جديد ولا تغيّر آرتًا أو opcode أو Core
Lock. كما أن `verified_iap` مغلق لأن موفّر Apple/Google حقيقي لم يُحقن بعد؛
اختبار adapter وهمي يثبت العقد فقط ولا يُعد تحقق متجر.

## التهديدات والضوابط

| التهديد | الأثر | الضبط المنفذ | المتبقي/التشغيل |
|---|---|---|---|
| العميل يرسل رصيدًا أو مكافأة | سك عملة بلا لعب | لا endpoint لمنح gameplay؛ المبلغ يُشتق من match مكتملة خادميًا | راقب منحًا بلا settlement |
| تكرار نهاية المباراة | مضاعفة المكافأة | `match_id` فريد في settlement وledger idempotent | retry مسموح ويعيد duplicate |
| AFK/leave ثم مكافأة | farming | snapshot مشاركين عند البدء؛ المقعد يجب أن يبقى بشريًا و`CONNECTED`، وأي timeout تلقائي للمقعد يلغي منح المباراة كاملة | تحقق ميداني من false suppression |
| تكرار نفس المجموعة/تواطؤ | farming | حد cohort ذري 8 مباريات/نافذة 24h وحد حساب يومي 20؛ لا wager أو transfer | Sybil متعدد الحسابات يحتاج تحليل سلوكي لاحق |
| سباق خصم/فتح | رصيد سالب أو duplicate | قفل wallet في معاملة، `CHECK balance >= 0`، ومفتاح فتح فريد | ضغط PostgreSQL مُدار مؤجل |
| إعادة receipt | شراء مضاعف | `(provider, provider_transaction_id)` فريد، receipt hash فقط، وقيد idempotency | يلزم sandbox حقيقي لكل متجر |
| تزوير قيمة SKU | رصيد زائد | القيمة تؤخذ من SKU server policy ومن ناتج verifier؛ أي mismatch مرفوض | تحديث قائمة SKU إجراء إصدار |
| تسريب receipt | استيلاء/خصوصية | لا تخزين token خام ولا telemetry له؛ HMAC hash فقط | وصول جدول الإيصالات مقيد تشغيليًا |
| بطاقة مدفوعة حصرية | pay-to-win | `gameplayEarnable=true` و`paidExclusive=false` إلزاميان لكل توسعة | تدقيق كتالوج موقّع قبل النشر |
| ملكية فردية تؤثر على السحب | أفضلية صاحب البطاقة | المساهمة استبدال واحد-بواحد ثم البطاقة في shared deck للجميع | الوصفة تُعرض قبل ready |
| استبدال بطاقة أضعف | شراء قوة | نفس `replacementClass` ونفس `powerBudget` خادميًا | budget يحتاج قرار تصميم موثق لكل بطاقة |
| public recipe حسب الملكية | نزاهة ranked | quick/public تستخدم active standardized recipe فقط؛ المساهمة private فقط | ranked الفعلي يبقى مرحلة لاحقة |
| عميل لا يعرف التعريف | crash/desync | capability فيها rules/catalog/definition ids؛ كل الجالسين يدعمون التعريف قبل المساهمة؛ join لاحق يُفحص | app update يسبق تفعيل المحتوى |
| تعديل manifest أو الأساس | كود/محتوى خبيث أو تغيير الآرت القديم | Ed25519 على canonical JSON؛ opcodes allowlist؛ إصدار forward-only؛ تعريفات ووصفات embedded غير قابلة للتعديل | المفتاح الخاص في KMS/HSM خارج المستودع |
| بطاقة تسبب loop/فقد/replay mismatch | فساد المباراة | بوابة ≥100k لكل تعريف ووصفة متأثرة، guard 5k، conservation وreplay لكل action | المتعة لا تثبت بالمحاكاة |
| تعطيل flag لا يرجع | incident ممتد | علم لكل بطاقة، إعداد مجهول يوقف الإقلاع، وregistry rollback إلى embedded classic | تمرين rollback قبل 5% |
| انحراف الرصيد عن ledger | سك/فقد عملة صامت | revision لكل قيد، مصالحة startup/5 دقائق/يدوية، وتجميد sticky لكل mutation مع بقاء اللعب | alert وربط runbook المشغل |
| catch-up إداري مسيء | سك عملة | endpoint داخلي فقط، admin token، حملة idempotent، eligibility/expiry، audit | RBAC وشبكة المشغل في النشر |
| خطأ إعداد جزئي أو typo في العلم | فتح مسار اقتصادي ناقص | أسماء وقيم أعلام الخادم مغلقة النوع؛ تبعيات catalog/wallet/friendly/IAP تفشل الإقلاع | راجع bundle قبل الطرح |
| حذف الحساب يمحو دليل المال | فشل تدقيق/خصوصية | wallet/unlock تحذف؛ ledger/receipt تبقى بلا account id | مدة الاحتفاظ القانونية تقفل قبل البيع |
| خطأ داخلي يتسرب عبر HTTP | كشف بنية/سر مشغّل | الأخطاء غير المصنفة تتحول إلى `SERVER_ERROR` 500؛ أكواد المجال المغلقة فقط تُعرض | تفاصيل الخطأ في سجل خادم محمي لا telemetry عميل |
| telemetry يربط الشراء بالشخص | انتهاك خصوصية | أحداث المنتج بلا account/receipt/transaction؛ تعريف بطاقة ونطاق رصيد فقط، لا الرصيد الدقيق | وصول بيانات الخادم منفصل |

## قواعد فشل آمن

- لا `receiptVerifier` حقيقي: `verified_iap=false` وroute يرجع 404.
- catalog signature أو schema غير صالح: لا تسجيل ولا تفعيل.
- عميل واحد لا يعرف البطاقة: لا اعتماد للوصفة لكل الطاولة.
- خطأ دفتر أو تعارض: لا تعديل جزئي؛ تعاد المعاملة كاملة.
- تجاوز حارس مدة/خروج/اكتمال: أوقف البطاقة ولا ترفع الجوائز لتعويض الضرر.

## المخاطر المقبولة مؤقتًا

- حدود cohort/day دفاع أولي وليست كشف Sybil نهائيًا. فعاليتها وfalse positives
  ضمن `P4-A01`.
- تسعير الكود provisional ومغلق للإنتاج حتى جلسات `P4-E01`.
- موفّر IAP الحقيقي واعتمادات المتجر غير موجودة، لذلك الشراء النقدي غير مشحون
  ولا يجوز وصفه جاهزًا.
- لا تعريف بطاقة جديد في هذه المرحلة؛ أي تعريف لاحق يعيد كامل بوابة P4 ولا يرث
  نجاح الكلاسيكي تلقائيًا.
