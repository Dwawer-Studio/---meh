# UIX-0 — الدستور البصري والنماذج المرجعية

التاريخ: 2026-08-29

الحالة: `UIX-0 Implemented / Production UI Unchanged`

هذه الشريحة تحسم لغة إعادة التصميم قبل نقلها إلى اللعبة. لا تعدّل شاشة إنتاج،
ولا قاعدة، ولا بطاقة، ولا اقتصادًا. النموذج مستقل تحت `prototypes/uiux-u0/`،
والتطبيق الحالي محفوظ بصريًا تحت `artifacts/uiux-u0/baseline/` للمقارنة.

## 1. نتيجة الشريحة

اعتمد اتجاه واحد اسمه **«الدائرة الحيّة / The Living Circle»**:

1. علامة Dwawer الدورانية تتحول من شعار ملصق إلى هندسة الدور والمقاعد.
2. اللاعبون يظهرون كمجلس واحد، لا badges منفصلة حول طاولة كازينو.
3. آرت البطاقات الحالي يبقى البطل ويُعرض دون crop أو recolor أو إعادة رسم.
4. الورق والحبر والأحمر يحلون محل البني/الذهب والزجاج العام.
5. العنصر المختلف في رسوم الاستديو يصبح قاعدة التركيز والحالة النشطة.
6. العربية تصميم أصلي، والإنجليزية تركيب مقابل، لا مجرد انعكاس آلي.

هذا يتفق مع مبدأ Hearthstone بأن الواجهة الغامرة تنطلق من عالم فني متماسك
وعملية تكرار، لا HUD منفصل عن الهوية
([GDC](https://gdcvault.com/play/1022036/Hearthstone-How-to-Create-an))،
ومع فصل Apple لمكونات الهاتف وتثبيتها بحسب الحواف بدل تصغير شاشة واحدة
([Apple](https://developer.apple.com/videos/play/meet-with-apple/243/)).

## 2. عقد القفل

### ملفات محمية بالبصمة

- `assets/cards/`: 61 ملفًا، أي 60 وجهًا وظهر بطاقة واحد.
- `deck.js`: وصفة القلب الحالية.
- `catalog/catalog-registry.js`: سجل الكتالوج.
- `shared/match-reducer.js`: مرجع الحالة والقواعد.

البصمات في:

- `docs/uiux-u0/card-assets.sha256`
- `docs/uiux-u0/protected-files.sha256`

اختبار `tests/uiux-u0-contract.test.js` يعيد حسابها، ولذلك يفشل UIX-0 إذا تغير
بايت واحد في أصل بطاقة أو ملف قاعدة محمي.

### ممنوع في UIX-1 وما بعدها

- استخدام أحمر Dwawer كلون لعب خامس.
- تعديل أصل بطاقة لتناسب الخلفية الجديدة.
- نقل قرار قواعد أو مؤقت إلى animation.
- إدخال متجر أو تاماشي في أول جلسة لإثراء المشهد.
- نسخ layout أو motion signature من لعبة عالمية.

## 3. الهوية والأصول

فُحص أرشيف `dwawer-logo` الأصلي في مساحة الاستديو. وُجد ملف Illustrator
مصدره SHA-256:

`608eeebdb802ed22f2fff3b974c59858f1113285b3023bad8dad3076d2d00316`

لم يُنسخ ملف المصدر إلى اللعبة؛ صُدرت فقط ملفات PNG المطلوبة كنسخ byte-for-byte:

- العلامة الملونة والحبرية والبيضاء.
- الشعار النصي الملون.
- دائرة اللاعبين الأربعة.
- حقلا الشخصيات للزخرفة والتركيز.

التفاصيل والبصمات في `docs/uiux-u0/brand-assets.json` و
`docs/uiux-u0/brand-and-font-assets.sha256`. لم يوجد ترخيص توزيع عام بجوار
الأرشيف، لذلك تسجل الأصول كهوية مملوكة للاستديو ومصرح بها لهذا المنتج، لا كأصول
عامة يعاد توزيعها منفصلة.

## 4. نظام اللون

المرجع القابل للآلة: `docs/uiux-u0/tokens.json`.

| الرمز | القيمة | الاستخدام |
|---|---:|---|
| `brand.signal` | `#EE3633` | العلامة، مسار الدور، focus edge، والحالة النشطة بلا نص أبيض صغير |
| `brand.signalDeep` | `#B9212B` | أزرار ممتلئة تحمل نصًا أبيض، بنسبة `6.33:1` |
| `brand.ink` | `#040707` | النص، الخطوط، والطاولة العميقة |
| `surface.paper` | `#F7F2E9` | القراءة والغلاف والنتيجة |
| `surface.paperBright` | `#FFFDF8` | البطاقات والسطوح المرتفعة |
| `surface.paperMuted` | `#E7DED1` | الحالات الهادئة والثانوية |
| `economy.tamashi` | `#3B716C` | تاماشي فقط؛ مادة مستقلة لا ذهب كازينو |

ألوان اللعب البرتقالي والبنفسجي والرمادي والأسود باقية كدلالة قواعد فقط. لا
يعتمد أي معنى حرج على اللون وحده؛ الرمز والنص والحافة جزء من الحالة.

اكتشف الفحص أن الأبيض على أحمر الهوية الصافي يساوي `4.03:1`، لذلك رُفض
استخدامه للنص الصغير. هذه ليست ملاحظة لاحقة؛ هي قرار token مثبت بالاختبار.

## 5. الخط

اعتمد `IBM Plex Sans Arabic` بوزني Regular وSemiBold للنموذج وللانتقال إلى
UIX-1 للأسباب التالية:

- تشكيل عربي واضح مع لاتينية متوافقة.
- WOFF2 محلي، بلا اتصال شبكة وقت التشغيل.
- ترخيص SIL OFL 1.1 محفوظ داخل المستودع.
- بنية عملية للنصوص الطويلة بدل استخدام الشعار كخط واجهة.

المصدر الرسمي يثبت دعم العربية وترخيص OFL
([IBM Plex](https://github.com/IBM/plex/)،
[الترخيص](https://github.com/IBM/plex/blob/master/LICENSE.txt)).

شعار «مِهْ» وشعار Dwawer يبقيان أصولًا مرسومة؛ لا يُستخدمان كبديل لنص حي.

## 6. عقد الشكل والأيقونات

- شبكة المسافات 4px.
- ثلاث درجات radius فقط: 12/22/34px.
- stroke هادئ 1px، قياسي 2px، focus 3px.
- الهدف المتكرر لا يقل عن 44 CSS px.
- الأيقونة خط دائري النهايات، بوزن واحد، بلا emoji للنظام.
- الإيموجي يبقى فقط داخل التواصل الاجتماعي عندما يكون هو المحتوى.
- الظل صلب قصير لسطوح الورق، لا glassmorphism ولا glow ذهبي.

أيقونات النموذج مرسومة كـSVG symbols داخل النموذج. في UIX-1 تنقل إلى sprite
مشترك وتستبدل كل إيموجي تنقل في الإنتاج.

## 7. النماذج المرجعية

المصدر التفاعلي:

`prototypes/uiux-u0/index.html`

صيغة الرابط:

```text
/prototypes/uiux-u0/index.html?screen=home&locale=ar&frame=portrait
```

القيم:

- `screen`: `home | table | results`
- `locale`: `ar | en`
- `frame`: `portrait | landscape`
- `capture=1`: يخفي أدوات النموذج ويملأ الإطار.

### الرئيسية

- CTA واحد «العب الآن» يجمع المحلي والسريع والأصدقاء بدل خمسة أزرار متساوية.
- بطاقة «مجلسك الأخير» تعيد المجموعة إلى الطاولة من السياق.
- التنقل الرئيسي ثلاثة أسطح فقط: الرئيسية، المجالس، البطاقات.
- المتجر داخل البطاقات، لا ينافس اللعب في أول شاشة.
- آرت البطاقات الفعلي مستخدم كما هو، مع رسم Dwawer كخلفية ذات معنى.

### الطاولة

- خلفية حبرية، لا طاولة كازينو بنية.
- ثلاثة خصوم ومقعد اللاعب يصنعون دائرة واضحة.
- مسار Dwawer الأحمر يعرض الاتجاه والمقعد النشط.
- البطاقة والمرمي في مركز القرار، واليد في منطقة الإبهام.
- portrait وlandscape تركيبان منفصلان؛ لا scale للصورة نفسها.
- سجل الحركة والصوت أيقونتان سياقيتان، وليس شريط تطبيق دائمًا.

### النتيجة

- تعرض سبب الفوز أولًا، ثم حصيلة المجلس، ثم تاماشي ومصدرها.
- «مرة ثانية» الفعل الأساسي، وجاهزية 3/4 جزء من نفس الشاشة.
- لا عملات متطايرة ولا مكافأة غامضة ولا خروج أقوى من الإعادة.

## 8. مصفوفة الصور

حُفظت 12 صورة مرجعية:

- 3 شاشات × AR/EN × `393×852` عمودي.
- 3 شاشات × AR/EN × `932×430` أفقي.

وحُفظت 10 صور baseline للواجهة الحالية عند `393×852`: الرئيسية، الأعضاء،
التعليمات، الإعدادات، الدعوة، المتجر، الأونلاين، الردهة، الطاولة، والنتيجة.

كل اسم وحجم وبصمة في `artifacts/uiux-u0/screenshot-manifest.json`. فحص المتصفح
مرّ على كل عنصر مرئي بعد تحميل الخط والصور؛ النتيجة `0` overflow في الحالات
الـ12، ومسجلة في `artifacts/uiux-u0/browser-audit.json`.

## 9. الحركة والتغذية الراجعة

العقد الكامل في `docs/uiux-u0/MOTION-STORYBOARD.md` ويغطي:

- لعب بطاقة عادية.
- عقوبة/سحب مع «ليش صار؟».
- انتقال الدور وعكس الاتجاه.
- نهاية الجولة والإعادة.
- البديل الكامل لـreduced motion.

الحدود المثبتة: إقرار اللمس ≤100ms، micro بين 120–220ms، الشاشة بين
260–420ms، ولا blocking بعد 450ms. المؤقت والقواعد لا ينتظران الحركة.

## 10. التحقق

بوابة UIX-0 تشمل:

```bash
npm run validate
npm run test:uiux-u0
node tools/uiux-u0-manifests.js
```

كما تدخل اختبارات العقد ضمن `node --test` و`npm run check`.

تتحقق البوابة من:

- HTML/CSS/JS للنموذج.
- بصمات الـ61 أصل بطاقة وملفات القواعد.
- بصمات الهوية والخط وترخيصه.
- نسب التباين المسجلة.
- وجود الصور الـ10 والـ12 وأبعادها وبصماتها.
- عدم اقتران النموذج بـreducer أو الكتالوج.

## 11. ما لم يتغير

- لم يتغير `index.html` أو `style.css` أو أي ملف تحت `game/`.
- لم يتغير `assets/cards/`.
- لم يتغير عدد البطاقات أو وصفة الـ60 أو أسماء البطاقات.
- لم يُفعّل شراء، متجر جديد، عملة، بطاقة، أو علم منتج.
- النموذج ليس production UI ولا يدّعي أنه كذلك.

## 12. بوابة الانتقال إلى UIX-1

تبدأ UIX-1 من هذا العقد فقط، لا من CSS الحالي ولا من اقتراح بصري جديد. أول
تنفيذها: نقل tokens والخط والأيقونات إلى طبقة UI مع fixture للمكونات، ثم إثبات
AR/EN وRTL/LTR و200% text و44px targets وreduced motion قبل إعادة بناء أي شاشة.
