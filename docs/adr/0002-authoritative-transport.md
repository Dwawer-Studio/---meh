# ADR-0002: سلطة المباراة وحدود PeerJS

- الحالة: مقبول مرحليًا
- التاريخ: 2026-08-28

## السياق

اللعب الحالي يجعل المضيف سلطة المباراة عبر PeerJS. هذا مناسب للتحقق الودي، لكنه
لا يثبت نزاهة نتائج تمنح تاماشي أو تؤثر في تصنيف؛ فالمضيف عميل قابل للتعديل.

## القرار

- يبقى PeerJS للنمط الودي خلال التحقق المغلق.
- لا تُمنح مكافآت اقتصادية موثوقة ولا تصنيف عام من نتيجة صادق عليها المضيف وحده.
- قبل تفعيل تاماشي، ينقل التحقق من الأفعال والإكمال ومنع الإعادة إلى خدمة خادمية
  صاحبة السلطة، مع مفاتيح idempotency وسجل تدقيق.
- يستخدم الخادم نفس `rulesVersion` و`catalogVersion` و`deckRecipeId` المسجلة في
  replay، ويرفض وصفة أو تعريفًا غير معروف.

## النتائج

لا يُعامل الاتصال الحالي كبنية اقتصاد آمنة. يمكن مواصلة اختبار المتعة الآن، لكن
بوابة P4 لا تُغلق قبل السلطة الخادمية.
